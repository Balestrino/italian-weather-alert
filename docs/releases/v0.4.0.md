# IWA v0.4.0 — faster public queries and processing repairs

This minor release builds on [v0.3.0](v0.3.0.md), reducing public query database
work and improving evidence-backed regional and municipal interpretation.

## Changes

- Public API/MCP reads use indexed version and verification lookups, batched
  document/municipality reads and per-operation reuse of source quality and
  evidence. Historical boundaries, independent fact limitations, publication
  revocation and complete saved-view pagination remain effective. Concurrent
  nested reads also work with a single database connection.
- Supported CFR criticality and vigilance graphics cover all 26 zones and seven
  risks in the verified retained formats, with PDF-page evidence, weather metadata
  and applicability. Intraday transitions and independent vigilance diagnostics
  preserve unknown fields and edition-specific legend gaps.
- Municipal processing preserves partial reopenings, independent prohibition
  scopes and supported COC activation validity. Literal JSON classification and
  oversized-PDF OCR recovery use immutable corrective catalogs. Unstated source
  fields remain explicit rather than inferred.
- Audited exact-version archive recovery permits bounded ordinary reprocessing
  while preserving prior results and archive guards. Observation reports retain
  scoped evidence, historical failures, independent municipal gates and missing
  cost metrics.
- Ordinary scoped Cittadino Informato collection and comparison workers support
  reviewed PDF dependencies. Comparisons preserve archived primary evidence and
  reevaluate retained records without new provider calls or admitting unsupported
  platform values as primary facts.
- Development can select `IWA_PUBLIC_IMAGE` for an isolated public-listener update;
  staging and production continue to use the shared `IWA_APP_IMAGE` selection.
- `golang.org/x/text` is upgraded to 0.41.0 to resolve the reachable
  [GO-2026-6629 vulnerability](https://pkg.go.dev/vuln/GO-2026-6629).

## Compatibility and upgrade

The 0.3.0 situation response paths, HTTP routes and MCP tools remain compatible.
OpenAPI and MCP implementation metadata identify 0.4.0. Reuse is confined to one
operation; subsequent requests reevaluate current controls and interpretation.
Consumers upgrading from an earlier version should also follow the
[0.3.0 situation migration](v0.3.0.md#api-compatibility).

Follow the [environment guide](../operations/environments.md) and
[release procedure](../operations/releases.md). Run the selected environment's
admin `migrate` command before replacing listeners and processing replicas. This
applies additive public-query lookup, archive-recovery and observation migrations
without changing previous checksums. Replace every active processing replica to
adopt the corrected catalogs and ordinary comparison behavior. Existing retained
interpretations require deliberate bounded reprocessing; upgrading does not
automatically replay them or enable collection, embeddings or publication.

Preserve the previous compatible image/configuration and retained data for
rollback. The optional development public-image override must be reviewed when
aligning all application surfaces. See [query latency](../operations/public-api-latency.md),
[municipal recovery](../operations/municipal-interpretation.md) and
[platform comparisons](../operations/cittadino-informato.md).

## Validation and pilot limits

Synthetic and isolated PostgreSQL tests cover interpretation, verification,
history, visibility, request isolation, timestamp precision and bounded query
counts. Development checks compare fixed-time responses, API/MCP pagination and
browser behavior. Publication requires CI, Coverage and Security passing for the
exact PR and merged main revisions.

This remains an internal Tuscany pilot. Verified retained formats and scoped
development collection do not establish complete municipal interpretation,
continuous platform availability or source acceptance. Referenced acts, source
acceptance and unsupported regional fields retain their documented limits.
Container publication, backup/restore readiness and production activation remain
separate operations. See [coverage](../coverage.md), [changelog](../../CHANGELOG.md)
and [OpenSpec progress](../../openspec/README.md).
