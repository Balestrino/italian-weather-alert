# IWA v0.1.1 — background processing controls

This patch builds on the [v0.1.0 internal-pilot baseline](v0.1.0.md). It makes background processing opt-in and gives operators equivalent territorial and source controls through the CLI and private admin panel.

## Changes

- Development and staging default startup excludes processing and backup workers. Production retains its separate worker profile.
- Regions can be enabled or disabled from `/admin/regions`; **Configura regione → Comuni** provides individual municipality controls, saved state, blocking reasons and audited history.
- CLI commands inspect, enable and disable regions, municipalities and source collection using the same validation as admin. Disabled territories block new acquisition, queued interpretation and manual execution while preserving child/source choices and historical reads.
- Native forms retain filters and pagination and work with keyboard navigation, JavaScript disabled, narrow screens and 200% zoom.

## Upgrade and validation

Follow the [environment guide](../operations/environments.md#territorial-and-source-activation) and [release procedure](../operations/releases.md). Apply migrations using the selected environment's admin service before updating listeners. The additive municipality migration preserves existing configured local-source eligibility; new municipalities start disabled. Source collection and public publication remain separate decisions.

Worker startup requires an explicit profile or service target. Profiles do not stop an already running worker: preserve the current collector until a scheduled handover and stop development/staging workers explicitly after controlled checks. These controls do not deduplicate work across environments. An older processing image that ignores municipal disablement is unsuitable after those controls are used; preserve additive data and keep processing stopped until a compatible rollback image is selected.

Go race tests, vet, command builds, Compose/environment regressions, isolated domain and processing integration suites, browser checks and reachable-vulnerability scanning passed during implementation. See [repository verification](../operations/background-processing-verification.md) for scope and the separately recorded development admin update. A partial admin update does not establish whole-environment image alignment.

## Pilot limitations

Source collection remains an internal Tuscany pilot. This patch does not establish source acceptance, nationwide coverage, public source access or production readiness. Image publication, backup/restore, capacity, routing and the production collector handover retain their separate release gates. See the [coverage tracker](../coverage.md), [changelog](../../CHANGELOG.md) and [OpenSpec progress](../../openspec/README.md).
