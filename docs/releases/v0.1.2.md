# IWA v0.1.2 — municipal acquisition and interpretation reuse

This patch improves municipal collection and avoids repeated interpretation of
reviewed Cascina HTML changes that contain only generated CSRF values. It also
includes the background and territorial controls described in the
[v0.1.1 preparation notes](v0.1.1.md), following the published
[v0.1.0 internal-pilot baseline](v0.1.0.md).

## Changes

- Source revisions can select the document-content container and authorize
  reviewed PDF attachments by exact HTTPS origin and directory, with bounded
  redirects and real PDF validation. Generic footer links are excluded while
  missing required attachments still fail visibly.
- Cascina listing dates support days with one or two digits. Correctly dated
  historical notices leave the recent checking window; unknown dates, explicit
  references and ongoing or unresolved measures retain their existing rules.
- Source-scoped Cascina preflight and interpretation manifests ignore only the
  exact reviewed CSRF values. Compatible validated results can be reused without
  another provider call; raw versions, meaningful changes and incomplete evidence
  remain independently recorded.
- Backoffice region ordering prioritizes enabled regions and shows current
  enabled/total municipality counts.
- Territorial guides record source-specific findings, exceptions and verification
  limits, with operational captures and settings kept private.
- Interpretation integration databases use Docker-assigned loopback ports,
  avoiding collisions with ports already published by other test containers.

## Upgrade and validation

Follow the [environment guide](../operations/environments.md) and
[release procedure](../operations/releases.md). Apply additive migrations with
the selected environment's admin service before updating listeners. Collection
and inference workers require explicit selection; territorial, source and public
publication choices remain independent.

Attachment permissions require an individually reviewed source revision. Cascina
interpretation reuse requires the existing source opt-in lists. Preserve provider
holds, retry limits and originals when reviewing stale pending work. See
[municipal attachment and reuse operations](../operations/municipal-attachments.md)
for configuration, verification and rollback.

Synthetic regressions and isolated PostgreSQL tests verify date-based selection,
attachment failure/recovery, source boundaries, contiguous equivalence and
validated result reuse without a second model call. Scoped development checks
verified complete collection and retained PDF reads. These checks do not establish
whole-environment image alignment or semantic acceptance of every source.

## Pilot limitations

This remains an internal Tuscany pilot. New non-equivalent documents still need
their own interpretation, and a provider quota hold can defer that work. This
release does not establish source acceptance, nationwide coverage, public source
access or production readiness. Container publication, backup/restore, capacity,
routing and collector handover retain their separate gates. See the
[coverage tracker](../coverage.md), [changelog](../../CHANGELOG.md) and
[OpenSpec progress](../../openspec/README.md).
