# IWA v0.2.0 — embedding controls and local processing

This minor release adds explicit embedding activation and reviewed local processing
to the [v0.1.2 pilot baseline](v0.1.2.md), with clearer administrative progress and
scoped development publication.

## Changes

- Global and per-source embedding switches in Sistema → Embedding and the admin
  CLI start disabled for existing and new sources. Both are required to admit
  embedding work; disabling preserves source choices and pending retry budgets.
  Provider configuration is loaded lazily, and ordinary linking continues while
  embeddings are disabled. Actor attribution and expected revisions audit changes.
- Reviewed article-body selectors, native PDF text and deterministic regional
  relevance checks reduce model calls while retaining original evidence,
  provenance, compatible reuse and conservative fallbacks.
- Queue maintenance is serialized across inference workers to prevent concurrent
  maintenance deadlocks. Operations pages distinguish complete job states,
  archives, pending document categories and historical attempts.
- Explicit development-only municipality publication adds scoped API/MCP views
  and revision-checked administrative choices. Staging and production retain
  their independent source-acceptance and publication requirements.
- The development public API binding supports other IPv4 interfaces; the admin
  listener stays private. OpenAPI and MCP implementation metadata identify 0.2.0.

## Upgrade and validation

Follow the [environment guide](../operations/environments.md) and
[release procedure](../operations/releases.md). Apply additive migrations with the
selected environment's admin service, including `068_embedding_control`, then
replace the admin listener and **every processing worker replica**. Earlier
worker images do not enforce the new embedding switches.

The former `IWA_SEMANTIC_LINKING_ENABLED` setting no longer activates embeddings.
Use the saved global and source controls after reviewing provider configuration;
enabling does not replay completed extractions or revive archived jobs. Keep
workers stopped when rolling back to an image that does not enforce these gates.
See [embedding controls](../operations/embedding-controls.md),
[local processing](../operations/local-processing.md) and
[development publication](../operations/development-publication.md).

Synthetic tests and isolated PostgreSQL checks cover disabled defaults, scheduling,
retry budgets, CLI/admin parity, local-processing provenance, publication scope
and concurrent queue maintenance. Software promotion requires passing CI,
Coverage and Security for the exact development and merged main revisions.

## Pilot limitations

This remains an internal Tuscany pilot. These features do not establish provider
availability, source acceptance, nationwide coverage, public service access or
production readiness. Source-specific local processing requires reviewed policy;
embedding enablement requires a configured, available provider. Container
publication, routing, capacity, backup/restore and production activation retain
their separate gates. See the [coverage tracker](../coverage.md),
[changelog](../../CHANGELOG.md) and [OpenSpec progress](../../openspec/README.md).
