# IWA v0.3.0 — situation summaries and source verification

This minor release builds on [v0.2.0](v0.2.0.md), making municipality situations
easier to read and connecting source evidence to regional and municipal facts.

## Changes

- The situation API/MCP response now centres on `processed_data` and
  `source_summaries`: source-supported conclusions, separate regional risks, local
  measures and operational phases, and individual regional, municipal and Cittadino
  Informato summaries. Compact references preserve documents, versions, official
  URLs and PDF pages. Pending document backlogs no longer produce situation rows
  or pages. Full-scope conclusions stay pinned across pages; freshness updates
  truthfully at delivery.
- Matching retained CFR criticality PDF vector maps provide per-risk, per-zone
  and per-day levels with page evidence. Explicit bulletin intervals are preserved;
  excluded areas remain distinct from green. Unsupported positions and conflicting
  editions stay unknown. This does not complete every zone or vigilance graphics.
- Validated ordinary primary municipal extractions and supported update links
  project into the shared domain with evidence and immutable knowledge boundaries.
  Literal date conflicts and unknown expiry stay explicit. Worker registration
  preserves historical local fallback configurations.
- Municipality-scoped Cittadino Informato API acquisition supports bounded
  discovery, versioned originals and dependency/retry guards. Persistent
  verification receipts distinguish primary support, unavailable checks, missing
  evidence, non-comparability and actual conflicts. Only supported primary values
  enter domain facts; republications are not counted as independent votes.
- Document and detailed fact operations expose scoped verification receipts with
  unpublished-channel evidence redacted. Source acceptance remains separate from
  acquisition, interpreted facts and development publication.

## API compatibility

The HTTP route and MCP tool remain unchanged. Consumers of the former raw
situation lists must update their data paths:

| Previous situation field | v0.3.0 field or operation |
| --- | --- |
| `local_measures` | `processed_data.local_measures` |
| `regional_products` | `processed_data.regional_alerts` |
| `operational_phases` | `processed_data.operational_phases` |
| `documents_requiring_attention` | Municipal source completeness statement; search and document operations for details |
| `coverage` | `source_summaries`; source coverage operation for full quality/acceptance details |

Processed facts use compact validity, `reliability`, affected limitations and
reference IDs rather than repeated quality and receipt structures. Regional
unknown/non-applicable and municipal undetermined validity remain explicit.
A channel with no publishable acquisitions is `not_collected` or unavailable,
never proof that it has no notices. Fresh available data does not imply complete
interpretation or accepted source coverage.

Earlier situation cursors with old collection positions return `cursor_mismatch`;
restart the query. A retained `dataset_version` can render the same pinned domain
knowledge in the current presentation. Search, document and coverage operations
and the normal metadata envelope remain available. OpenAPI and MCP implementation
metadata identify 0.3.0. See [response fields](../backend/public-api-mcp.md#situation-response)
and [saved views](../backend/public-views.md).

## Upgrade and validation

Follow the [environment guide](../operations/environments.md) and
[release procedure](../operations/releases.md). Run the selected environment's
admin `migrate` command before replacing listeners/workers; it applies the additive
`068_multi_source_verification` migration through public-query migration. Replace
all processing replicas to adopt the municipal projection and compatible local
fallback registration. Preserve source, territorial, embedding and publication
controls; acquisition and platform comparison are enabled separately in reviewed
scopes. Existing retained extraction results are not automatically replayed by
this software upgrade.

Synthetic tests and isolated PostgreSQL checks cover verification/admission,
projection, source visibility, temporal history, vector interpretation and API/MCP
parity. Rich situation tests verify pagination, deduplicated evidence, missing
channels, incomplete interpretation and truthful saved-view freshness. The scoped
development API/MCP verification retains regional facts and documented municipal
measures while substantially reducing response size. Promotion and tagging require
CI, Coverage and Security passing for the exact revisions.

## Pilot limitations

This remains an internal Tuscany pilot. Source acceptance, municipal completeness
and conflicting operative dates, all-zone regional graphical interpretation and
continuous Cittadino Informato collection remain separate work. The bounded
platform trial does not populate the operational database automatically or certify
continuous availability. An undetermined restriction is documented, not confirmed
in force. Image publication and production activation retain their separate
release gates. See [coverage](../coverage.md), [changelog](../../CHANGELOG.md) and
[OpenSpec progress](../../openspec/README.md).
